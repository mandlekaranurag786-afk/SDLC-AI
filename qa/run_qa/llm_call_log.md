# LLM Layer & Workflow Analysis

## Robustness & Error Handling
- **Truncated Responses:** `llm.py` line 66-69 raises an `LLMServiceError` if `finish_reason == "length"`. It is NOT retried unchanged. This forces the system to either abort or handle it at a higher level (UI shows an error).
- **JSON Parsing Robustness:** `llm.py` `parse_json` attempts `json.loads`. If it fails, it uses regex `r"\{.*\}"` (`re.DOTALL`) to extract the JSON block. This handles markdown formatting ` ```json ` blocks robustly. CODE-LEVEL.
- **Refinement Loop:** Bounded. `agent.py` line 28 has `MAX_REFINEMENT_ITERATIONS = 2`. The loop terminates if issues are resolved or iterations reach this limit. CODE-LEVEL.
- **Missing/invalid key, timeout, rate limit:**
  - Missing key errors before LLM call (`llm.py` L26).
  - Rate limits are caught (`RateLimitError`), and it does exponential backoff retries (`time.sleep(65 + attempt * 20)`).
  - General exceptions retry with backoff.
  - If it fails ultimately, an `LLMServiceError` propagates up to `main.py`, which catches it and returns `HTTP 503`. The UI receives a clean HTTP error.
  - **State saved:** State is saved at the phase boundaries. If generation fails, the session is resumed from the `ready_for_generation` or `asking_questions` stage. The user can just request `/generate` again. CODE-LEVEL.
